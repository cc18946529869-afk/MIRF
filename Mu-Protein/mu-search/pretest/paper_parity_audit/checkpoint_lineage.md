# Checkpoint 的训练来源

目标文件是 `muformer-l-BLAT_ECOLX_Ranganathan2015_CFX.pt`。

## 论文写明的监督

CFX 模型用 Stiffler、Hekstra 和 Ranganathan 2015 的 TEM-1 单点突变效应做微调，选择条件是头孢噻肟，规模大约 5,000 条。文件名里的 Ranganathan2015 和 CFX 与这条引用对应到文献，还没有对应到某一次具体划分。

论文没有写这次微调的 epoch、学习率、最佳验证相关，也没有把 0.566947 写成结果。正文的 0.94 和图注的 0.92 是 16 个 MIC 变体上的 Spearman，不是训练日志里的验证相关。

PMLM 的 UR50 是无监督预训练语料。它不是这份头的适应度标签，也不能用来回答监督覆盖了哪些突变阶数。

## 本地文件能够验证的

转换清单 `muformer.manifest.json` 记录：

- 源路径是仓库里的那份 `muformer-l-BLAT_ECOLX_Ranganathan2015_CFX.pt`
- `source_bytes` 是 8100983131
- `source_sha256` 是 `1f8e55dd1aa57df4b427b74137f1f474064a7b548d1f35fb1686cebf9a8e1d8d`

这个哈希和事先给出的值相同。本次没有重新读取 8.1 GB 文件来重算哈希，也没有从 Figshare 下载到一份带官方校验值的副本。Figshare API 返回 403。因此清单证明的是本地转换记录，不是一次新的官方发布核对。

同目录的 `muformer.config.json` 只有训练日志：epoch 285，`val_loss` 0.0680385，`best_corr` 0.566947。没有训练文件名，没有划分比例，没有突变阶数。

本地 ProteinGym v0.1 的 `BLAT_ECOLX_Stiffler_2015_{train,valid,test}.tsv` 合计 4996 条，相对搜索用的 286 位野生型全部是单点突变，train、valid、test 两两不重叠。这个规模和“大约 5,000 个单点”一致。配置没有引用这三份文件，所以它是一份符合论文描述的本地单点表，不是这份 checkpoint 的已证实训练集。另一条研究里用过其中 train 的子集；那次实验也不是这个 pt 的训练记录。

`mmc4-cfx.aligned.tsv` 在当前工作树和主工作区里没有找到。

`esbl_sequences.csv` 有 104 条，101 条长度 286、3 条长度 285。论文评估写的是 105 个 ESBL。这两个数字不同，不能把本地文件当成那 105 条的完整副本。

## 监督阶数能说到哪一步

论文明确说的监督是单点突变。它同时报告，这个单点模型在 16 个 MIC 变体上和实验相关，其中 11 个是高阶，而本地这 16 条的最高阶数是 4。所以论文主张的是：单点监督可以泛化到这一小组最高 4 阶的变体。论文没有给出 7–10 个突变的 CFX 测试结果。

本地配置不能把训练阶数直方图算出来。能验证的只有：存在一份 4996 条的单点 Stiffler 划分；checkpoint 的文件名和论文的数据来源同名；验证日志没有阶数。把“这份 pt 的适应度标签只含单点”写成已经由权重文件证明，证据不够。把它写成“论文如此描述 CFX 微调，而本地能找到的对应公开表确实全是单点”，这两句可以同时成立。

本次 16 条推理使用的是转换后的 safetensors，没有反序列化原始 pickle。野生型分数是 −0.072684437。先前同一次转换在 GPU 上记录的景观分数是 −0.072684407。两者相差约 \(3\times10^{-8}\)。搜索里保存的野生型分数就是这个数，所以这 16 条和六次预实验用的是同一个未归一化打分函数。模型处于 eval，头里的 BatchNorm 使用 checkpoint 的滑动统计，不用这 16 条自己的批统计。
