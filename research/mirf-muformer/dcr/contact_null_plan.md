# 接触零模型计算方案

草稿。2026-11-19 夜，用户审查结论仍是 HOLD，不批准改代码，正式 100 次计算是 NO-GO。本文件这一版只改缓存、身份锁定和核对规格。能量定义、温度、\(B\)、100 次、MI、四项判定和接触协议不动。做完固定交换预算并不表示终态已经比独立列置换更近，也不表示这些轨迹服从 Boltzmann 分布或是均匀零样本。\(1/101\) 只是描述性排名。不创建四个程序，不启动拟合。

这是距离约束的列交换零模型，不是已经充分控制系统发育的零模型。即使五个间隔组全部通过，也不写成已经排除系统发育效应。

下文路径都在 `research/mirf-muformer/` 下。

论文贡献沿用已经接受的假设：按五个序列间隔组，把已发布的 Precision@L、这个列交换零模型、加权 MI、APC-MI 放在同一套接触协议下比较。方案不加网络层，不改 Potts 公式，不加 14 维特征。

求解器不新写。零模型每个位点调用一次 `potts_fit.fit_site`，用它的默认参数：`lambda_h=0.01`，`lambda_j_prime=0.005`，`q=21`，`opt_tol=1e-5`，`prog_tol=1e-9`，`corrections=100`，`max_iter=500`，`max_fun_evals=1000`，零初值。`weight_total` 传入该次自己的 \(M_{\mathrm{eff}}\)。`potts_fit.stopping_status` 不把 `prog_tol` 当作停止条件；成功只有 `status=="converged"` 且梯度无穷范数不超过 \(10^{-5}\)。线搜索仍是 `potts_fit.strong_wolfe`，\(c_1=10^{-4}\)，\(c_2=0.9\)，一次最多 25 次求值。这些数不因某次精度、Pearson 或梯度而改。

### 算法 1：汉明距离约束

读的是 Rodriguez Horta 与 Weigt，*PLOS Computational Biology* 2021，17:e1008957，材料与方法里的 Null model II，以及伴随代码 `Null_models_I_and_II.jl` 的 `Energy`、`delta_d!` 和 `dE`。正文式 (5) 在页面上没有把符号渲染出来。代码把能量定义成归一化汉明矩阵全体元素的平方差之和，增量为负则接受，否则以 \(\exp(-\Delta E/T)\) 接受。散文写的是 Frobenius 范数，代码最小化的是这个范数的平方。方案采用平方，和代码的 `Energy` 一致。

用这些：距离覆盖比对里的全部序列；gap 与 20 种氨基酸同是字母表里的一个符号；交换只发生在一列的两行之间，列的符号多重集因此不变；单次交换的接受概率是 \(\min(1,\exp(-\Delta E/T))\)；从各列独立置换出发。论文里的 Null model I 只作为这个初值。

这是 Null model II 的固定预算分组扫描变体，不是原算法的逐步复现。原实现每一步随机选一个列和两个行，再尝试这一次交换。这里先均匀抽取一个无序行对，再按列号 0 到 262 顺序扫描。目标能量和局部增量继承原方法；提议调度是这里的改造。一次固定行对、固定列的交换本身可逆，对这一次交换使用上述接受概率没有问题。整个分组扫描加上变温轨迹不是原论文的随机单步采样，不能把 100 份终态说成已知平衡分布的独立样本，也不能说成 Boltzmann 分布的抽样。

放下这些：不把 Null model I 的结果拿来拟合或判定；不用 Null model III、FastTree 和 Felsenstein；不用他们不加权的 plmDCA、重原子接触、间隔大于 4、50 次和 z 分数；不把 Pearson 高于 0.97 当作准入；不删重复行；不用他们的字母编码，沿用 `mature_codes.npy` 里 0 为 gap、1–20 为氨基酸的编码；不把 \(N\times N\) 距离矩阵放进内存，也不按他们的自适应降温、退回历史最优、以及从自然比对加热的 `shuffle_alignment` 来停。他们的 `num_iter_max=20000000` 是小家族、矩阵可以常驻内存时的上限，不搬过来。

生产入口先检查矩阵是 \(209644\times 263\)、编码在 0–20。不对就停。距离和交换的基本运算按传入矩阵的行数、列数工作，合成测试才能用小矩阵。

记行数 \(N=209644\)，列数 \(L=263\)。无序对 \(N(N-1)/2=21975198546\)。整数距离 \(d(i,j)\) 是两行编码不同的列数，gap 与 gap 算相同，gap 与氨基酸算不同。归一化 \(h=d/L\)。能量是双方阵里全部非对角元素的平方差

\[
E=\sum_{i\neq j}\bigl(h_{\mathrm{cur}}(i,j)-h_{\mathrm{tgt}}(i,j)\bigr)^2.
\]

对角是 0。这份 \(E\) 与他们代码对全矩阵求和的 `Energy` 相同。生产时不保存、不分配这份矩阵。

一次列内交换：列 \(k\) 上两行 \(m,n\) 的符号是 \(a\neq b\)。对每一个其他行 \(j\)，设它在该列的符号为 \(c\)。整数增量

\[
\delta_j=\delta d(j,m)=\mathbf{1}[c\neq b]-\mathbf{1}[c\neq a]\in\{-1,0,+1\},
\]

\(\delta d(j,n)=-\delta_j\)。\(m\) 与 \(n\) 彼此的距离不变，因为两行在这一列原来不同，交换后仍然不同。

缓存是两条残差距离，不是四条独立距离：

\[
r_m(j)=d_{\mathrm{cur}}(j,m)-d_{\mathrm{tgt}}(j,m),\qquad
r_n(j)=d_{\mathrm{cur}}(j,n)-d_{\mathrm{tgt}}(j,n).
\]

抽到一对时扫描一次当前比对和一次原始比对，算出四条整数距离，立刻相减，之后只保留 \(r_m\) 和 \(r_n\)。能量定义仍是上面的 \(E\)，\(h=d/L\)。有序对上的平方增量化简后，

\[
\Delta E=\sum_{j\notin\{m,n\}}\frac{4}{L^2}\bigl(\delta_j(r_m(j)-r_n(j))+\delta_j^2\bigr).
\]

它与「对称矩阵各算一次、平方展开带系数 2」是同一个量。\(N=3\)、\(L=1\)、当前与目标同为 \([0,1,0]\)、交换前两行时，这个式子给出 \(\Delta E=4\)，六个有序对重算也是 4。先用交换前的残差算 \(\Delta E\)。接受之后才交换两个格子，并更新

\[
r_m(j)\leftarrow r_m(j)+\delta_j,\qquad r_n(j)\leftarrow r_n(j)-\delta_j.
\]

目标侧不再单独保存。拒绝则两条残差都不改。

提议预算固定为 \(B=8\times 209644=1677152\) 次「两行在该列符号不同」的提议。这个整数在看到任何零模型距离之前写死。它不等于 0.97，也不随 Pearson 或能量提前停止。每个重复恰好做完 \(B\) 次。

随机流是 NumPy 的 `SeedSequence([20261119, 编号])` 配 `PCG64`。主种子 `20261119` 只属于这一套接触零模型，不是 Bootstrap 的正式种子。顺序是：按列号 0 到 262，每列做一次独立的行置换。这只是初值。然后重复抽取两个不同的行，无序对在 \(N(N-1)/2\) 对里均匀抽取。抽到一对之后，只扫描这一次，得到 \(r_m\) 和 \(r_n\)。然后按列号 0 到 262 检查。符号相同的列不计数、不抽均匀随机数。符号不同才算一次提议：\(u\) 取 \([0,1)\) 上的均匀数，\(\Delta E<0\) 或 \(u<\exp(-\Delta E/T)\) 就接受。温度只由提议序号 \(t=0,\ldots,B-1\) 决定，

\[
T(t)=10\times\Bigl(\frac{2/(10\times 209644)}{10}\Bigr)^{t/(B-1)}.
\]

起点 10，终点 \(2/(10N)\)。中间按序号几何降温，不再按接受率改温度，也不退回以前的比对。预算在某一对的中途用完，就停在这一次，不把该对剩下的列做完。

一对的两条残差用完即丢。下一对重新扫描。一次提议不再回头读其余 \(L-1\) 列，也不再读四条独立距离。\(\Delta E\) 只读 \(r_m\)、\(r_n\) 和该列符号。

无序对的抽取是对称的，单次交换也可逆。列按固定顺序 0 到 \(L-1\) 走，只有当前两个符号不同才发出提议。一次接受之后，下一步是同一对的下一列，不是把这一列再换回来。因此这不是一步一交换的对称 Metropolis 核。100 条轨迹是固定预算的启发式退火，不是 Boltzmann 抽样，也不是严格随机化检验的独立均匀样本。

内存里放两份 `uint8` 比对，\(2\times 209644\times 263=110272744\) 字节，再加两条 `int16` 残差，\(2\times 209644\times 2=838576\) 字节。不分配 \(N\times N\) 距离矩阵，也不在提议期间保留四条距离。

计算量分两截。换一对行时，当前比对和原始比对各扫描一次，每次 \(NL=209644\times 263\) 次符号比较，然后收成两条残差。这种扫描的次数等于抽出的行对次数：最少 \(\lceil B/L\rceil=6385\)，最多 \(B=1677152\)。每一次提议读两条残差，单次重复是

\[
2BN=2\times 1677152\times 209644=703209707776.
\]

这就是约 \(7.032\times 10^{11}\) 次数组元素读取。早先把四条独立距离算成 \(4BN\)，那一说作废。这不是每次提议再把 263 列重比一遍。100 次的残差读取约 \(7.032\times 10^{13}\)。每个重复记录墙钟秒数、行对扫描次数、提议次数、接受次数和每秒提议数，并按列记录下面的位点计数。这些数是该次运行的吞吐量，不事先当成已经测到的速度，也不用来改 \(B\) 或温度。

温度公式不改。提议序号切成 10 段，每段 \(B/10=167715\) 次，最后一段 \(167715+2\) 次，因为 \(10\times 167715=1677150\)，还剩 2 次。每一段报告提议数、接受数、接受率，以及该段 \(\Delta E\) 的最小值、25% 分位、中位数、75% 分位、最大值和平均值。分段在看到任何零模型之前按序号写死，不按接受率重新划段。

同一重复另记长度为 263 的两个整数：每个位点的提议次数和接受次数。列 \(k\) 发出一次提议，位点 \(k\) 的提议数加 1；该次被接受，接受数加 1。扫描顺序不改。这两个数组用来检查固定从 0 扫到 262 是否让靠前的位点系统性更早、因而在更高的温度上被提议。它们不参与四项判定，也不用来改温度或列顺序。

拟合读的是保存下来的 `msa.npy`。同一 NumPy 的 `SeedSequence` 应能把种子重放成这份比对；重放与文件不一致就停，不用重放结果覆盖文件。每个重复同时记下 NumPy 版本和算法名 `column_swap_hamming_20261119`。

Pearson 在生成结束后对全部无序对算一次，只写入报告，不剔除、不重跑。它不需要距离矩阵。列计数完全决定 \(\sum d\)，列多重集不变时当前比对与原比对的 \(\sum d\) 相同。平方和与叉积用列对的 \(21\times 21\) 联合计数：两列上符号为 \((a,b)\) 的行数是 \(n_{ab}\) 时，

\[
\sum_{i<j}\mathbf{1}_{\mathrm{diff}}\mathbf{1}_{\mathrm{diff}'}
=\binom{N}{2}-\sum_a\binom{n_{a\cdot}}{2}-\sum_b\binom{n_{\cdot b}}{2}+\sum_{a,b}\binom{n_{ab}}{2}.
\]

\(d\) 对列求和，所以 \(\sum d_{\mathrm{cur}}d_{\mathrm{tgt}}\) 是当前列与原始列的全部列对之和。Pearson 用这些和。某一边方差为 0 时，Pearson 记成没有形成，该重复仍然保留。能量 \(E\) 也可以由 \(\sum(d_{\mathrm{cur}}-d_{\mathrm{tgt}})^2/L^2\) 核对。

### 算法 2：MI 的零频率项

MI 只在原始 MSA 上算一次，不在零模型比对上重算。字母表是含 gap 的 21 态。权重是 `prep/neighbor_counts.tsv` 的正式 \(m_i\)，\(w_i=1/m_i\)，\(W=\sum w_i\)。这个和必须与 `potts_fit.OFFICIAL_M_EFF` 逐位相同，否则停。不调用 `block_index.pairwise_mutual_information`：那个函数按行数平均、不加权、不做 APC，当前入口也没有调用它。

\[
p_i(a)=\frac1W\sum_s w_s\mathbf{1}[x_{si}=a],\qquad
p_{ij}(a,b)=\frac1W\sum_s w_s\mathbf{1}[x_{si}=a]\mathbf{1}[x_{sj}=b].
\]

对数是自然对数。和式只加入 \(p_{ij}(a,b)>0\) 的项：

\[
I_{ij}=\sum_{a,b:\,p_{ij}(a,b)>0}p_{ij}(a,b)\ln\frac{p_{ij}(a,b)}{p_i(a)p_j(b)}.
\]

\(p_{ij}=0\) 的项按连续极限取 0，不加入，也不加伪计数、不加 \(\varepsilon\)。边际由同一套权重的列和得到。出现 \(p_{ij}>0\) 而边际为 0 时，当作实现错误停止，不用伪计数补上。没有出现的氨基酸留在 21 态里，它的整行联合都是 0，这些项都不进入和式。

APC 调用 `contact_validation.average_product_correction`。对角先置零，分母是 262，背景是全部 263 个位点。换一个正的对数底会把全部 \(I_{ij}\) 乘上同一个正常数，APC 后的名次不变。保存下来的矩阵固定用自然对数。APC 的背景为 0 而导致函数拒绝时，MI 这一臂没有形成，五个组的 MI 比较都不成立；不为此引入伪计数。

报告里写明：MI 和 APC-MI 是含 gap 的 21 态基线。已发布的 Potts 接触分数是去掉 gap 态之后的 20×20 氨基酸块。两者不是同一个 20 态对照。这个差别不取消四项里的 MI 比较，也不把 MI 说成与 \(J^\star\) 同构。

### 算法 3：重拟合

每个编号先对保存的比对调用 `sequence_weights.sequence_weights`。定义是 \(c_{ab}\ge 211\)，\(w_i=1/m_i\)，\(M_{\mathrm{eff}}=\sum 1/m_i\)，重复行不合并，gap 与 gap 算相同。`block_rows` 用默认值 64。不改用真实比对的 \(m_i\)，也不改用 47900。

\(q_j\) 调用 `solver_v2._background`，权重是该次的 \(w_i\)，`weight_total` 是该次的 \(M_{\mathrm{eff}}\)，`q=21\)。这就是

\[
q_j(b)=\frac{M_{\mathrm{eff}}}{M_{\mathrm{eff}}+1}f_j(b)+\frac{1}{M_{\mathrm{eff}}+1}\cdot\frac1{21}.
\]

\(q_j\) 按用户要求计算并保存。它不进入 `fit_site`，不进入 MI，也不进入接触分数。接触排序不读它。已发布接触分数用的是均匀平均后的 \(J^\star\)，不是 \(q_j\) 加权的规范。

然后 263 个位点各调用一次 `potts_fit.fit_site(msa, w, site, M_eff)`。40 个进程，每个进程 1 个 OpenMP 线程，与 `full_fit.py` 的进程安排相同。不热启动，不改 \(\lambda\)，不放宽容差，不因为 Precision 高或低而重跑。

断点恢复沿用 `bootstrap_fit.py` 的身份管理，不把「`site_XXX.npz` 存在」当成「它属于当前重复」。不直接调用 `make_identity`：那个函数把抽样长度固定成 47900，并把总权重固定成官方 \(M_{\mathrm{eff}}\)。token 的算法与 `_token` 相同：锁定字段按 `sort_keys=True`、`separators=(",", ":")` 的 JSON 做 SHA256。写入使用已有的 `atomic_json`、`atomic_npy` 和 `atomic_savez`。读取规则与 `_require_existing_sites`、`open_replicate` 相同：空文件、读不出 token、token 不一致，都停止，不复用，也不在原文件上继续拟合。

每个编号的 token 锁定这些字段，缺一不可：

| 字段 | 内容 |
| --- | --- |
| `role` | `contact_null` |
| `replicate_id` | 1 到 100 |
| `seed` | 主种子 20261119 与该编号 |
| `original_msa_sha256` | `prep/mature_codes.npy` |
| `null_msa_sha256` | 该编号的 `msa.npy` |
| `algorithm` | `column_swap_hamming_20261119` |
| `code_revision` | 当前 git HEAD |
| `fit_parameters` | `fit_site` 的默认 \(\lambda\)、容差、迭代上限、\(q=21\)、零初值，以及 \(c_{ab}\ge 211\) 的权重定义 |

`msa.npy` 与清单先原子写入。清单里的 `null_msa_sha256` 必须等于当前 `msa.npy`；不相等就停止。位点文件里写入同一个 `identity_token`。某个位点文件缺失，才补算这个位点。文件在而 token 不对，停止，不把另一份比对的参数接着用。不同编号的目录不共享位点文件。

一个位点通过，当且仅当与 `bootstrap_fit._site_accepted` 相同的条件成立：`status` 为 `converged`，梯度无穷范数有限且不超过 \(10^{-5}\)，目标有限，迭代不超过 500，函数求值不超过 1000，参数有限。`armijo_fallback` 不单独判失败。`line_search`、`nonfinite`、`max_iter`、`max_eval`、`ascent_direction` 都是未通过。

任一位点未通过，就不调用规范转换，不写 `j_star.npy`，五个组的 Precision@L 都记为没有形成。诊断和失败位点名单保留。不另抽编号，不把 001–100 改成少于 100 个。

全部通过之后才写 \(J^\star\)。SHA256 是这块连续 float64、C 顺序字节的哈希。形状必须是 \(263\times263\times21\times21\)，并且 \(J_{ji}(b,a)=J_{ij}(a,b)\)；否则这份 \(J^\star\) 没有形成。

每个编号目录 `dcr/contact_null/replicate_001` 到 `replicate_100` 保存：上面的身份字段和 token、NumPy 版本；`msa.npy`；每列 21 态计数与原始列相同的核对；Pearson、能量、\(B\)、接受次数和温度端点；10 段温度诊断；每个位点的提议次数和接受次数；\(m_i\)、\(w_i\)、\(M_{\mathrm{eff}}\) 和 \(q_j\)；263 个位点的拟合诊断；形成了才有的 \(J^\star\) 及其 SHA256；五个组的 Precision@L，以及只供报告的 @L/2、@L/5 和 AUPRC。

### 耗时

三笔都是外推，不是保证。记录里的 46 是抽测位点数，不是 46 分钟。一次 263 位点、47900 行的 Bootstrap 约 48 分钟。一次全长拟合约 2.84 小时。不使用由 46 分钟按行数乘出的 3.36 小时，也不把 100 次写成 14 天。

生成：一次双比对的两行全长扫描没有测量。在假定每次扫描 0.02 秒的前提下，100 个重复的墙钟上界是每次提议都扫描，约 \(1677152\times 0.02\times 100=930\) 小时；下界是每次扫描摊满 263 个不同符号列，约 3.5 小时。实际扫描次数取决于当时两行有多少列不同，落在这两端之间。Pearson 的列对计数远小于这个上界，不另报墙钟。

权重：`sequence_weights.neighbor_counts` 在 209644 行上没有墙钟。它做完全部无序对的 263 列比较，次数是 \(5779477217598\)，不随近邻数减少。`prep/neighbor_summary.json` 的 `scan_seconds` 134.72 是真实比对上另一条提前终止扫描，不乘 100，也不当成这个函数的耗时。\(6.29\times 10^{10}\) 不是那份摘要里的计数器，而是全部候选对 \(C=835184036\) 与平均读取列数 75.35620804 的乘积。134.72 秒是 `prep/neighbor_summary.json` 的 `scan_seconds`，来自后来写出 \(m_i\) 的那次提前终止扫描，不是 `neighbor_counts` 的测量。用这个乘积除以 134.72 秒，得到约 \(4.7\times 10^8\) 列/秒，再除 `neighbor_counts` 的全部列比较次数：一次约 3.4 小时，100 次约 340 小时。这是借用另一个内核的速率。

拟合：一次全长用 2.84 小时，100 次约 11.8 天。权重和生成都不在这 2.84 小时里。编号按一次一个重复来跑，重复内部才用 40 个进程。

| 假设里的一步 | 落到 |

| 每个重复按自己的行重算权重 | `contact_null_fit.py` 调用 `sequence_weights.sequence_weights` |
| 用得出已保存 \(J^\star\) 的估计重新计算 | `potts_fit.fit_site` 一次，再 `bootstrap_gauge.gauge_parameters` |
| 已保存的真实 \(J^\star\) 不替换 | 只读 `reference/j_star.npy`；新 \(J^\star\) 写在 `dcr/contact_null/replicate_XXX/` |
| 接触协议不改 | `contact_null_metrics.py` 调用已有接触函数 |
| 含 gap 的 21 态加权 MI，以及同一个 APC | 算法 2 |
| 五个组分别做 Precision@L | `evaluate_sets` 的五个键 |
| 合取不进 μFormer，不加 14 维 | 无调用 `potts_features.py`，无训练入口 |

合成测试在 `test_contact_null.py`，不读 209644 行，不调用 `fit_site`。增量能量以方案写出的平方和为唯一依据，不对照外部 Julia。实现前必须有下面这组核对，而且它先于任何生产生成：

1. 随机生成小型整数 MSA，编码在 0–20，至少有一列全是 gap。
2. 随机选一列和两行，两行在该列的符号不同。
3. 用全部有序对重算交换前的 \(E\) 和交换后的 \(E\)。
4. 增量 \(\Delta E\) 与这两个完整值的差一致。
5. 在交换后的矩阵上做同两行、同一列的反向交换。反向的增量等于正向增量的相反数；增量为 0 时两边都是 0。
6. 正向和反向之后，每一列的 21 态计数都与交换前相同。被交换的两行彼此的整数距离在符号不同时不变。
7. 在另一份小型 MSA 上直接构造完整汉明距离矩阵。用这个矩阵算出的 Pearson，与用 \(21\times 21\) 列对联合计数算出的 Pearson 相同。
8. 用完整矩阵算出的 \(E\)，与用列对联合计数算出的 \(E\) 相同。
9. 连续做多次都被接受的交换。每接受一次，残差缓存给出的 \(\Delta E\) 等于完整重算的能量差，更新后的 \(r_m,r_n\) 等于用两份完整比对重新算出的残差。单次交换正确不代替这一项。

另外核对：有零联合频率的加权小比对上，MI 全部有限，并且等于手算时跳过零项的自然对数和式；100 个槽里某一号的 Precision@L 为空时，该组不成立，编号仍是 001–100，不出现 101；输出指到受保护的 \(J^\star\) 路径时写入被拒绝，测试前后该文件的大小和 SHA256 不变；token 不一致或缺失时停止且不复用该位点文件。这组测试还没有写，因为代码修改尚未批准。

## 4. 对照怎么配

五个间隔组分开判定，互不替代。某一组四项同时成立，才支持这一句归因：已发表的带权估计器，在保留列边际、并把成对汉明距离拉向原比对作为生成目标的比对上，没有再现这个 Precision@L，并且这个 Precision@L 也高于同一协议下的 MI 和 APC-MI。这里不放入显式的功能性残基补偿。汉明距离是各位点差异的和，平方之后有位点之间的交叉项，所以全局距离约束仍会产生统计共变。不把这些比对说成消除了全部统计共变，也不说成完全无耦合，更不说成系统发育树已经控制住了。拉近是接受规则的目标。终态是否更近，只看报告里的 Pearson 和能量。做完 \(B\) 次并不表示终态已经比独立列置换更近。Pearson 高也不排除系统发育效应。

四项是：

| 判定条件 | 必须满足 |
| --- | --- |
| 零模型重复 | 编号 001–100 都形成该组 Precision@L |
| 零模型比较 | 真实值严格大于全部 100 次 |
| MI 比较 | 真实值严格大于 MI |
| APC-MI 比较 | 真实值严格大于 APC-MI |

相等不通过。比较用 `ranking_metrics` 的 `precision_at_l`。这些分数都是长度 263 的 0/1 前缀的均值，相差一格就是 \(1/263\)。

@L/2、@L/5 和 AUPRC 写入同一张表，不参与四项。固定预算的降温轨迹不是从已知零分布里的均匀样本，所以

\[
r=\frac{1+\#\{\pi(T_b)\ge \pi(s_J)\}}{101}
\]

只作为描述性的 Monte Carlo 排名，不是经过校准的显著性概率。同时报告大于或等于真实值的次数，以及真实值在这 100 个已形成数值里的名次。100 次都形成且全部严格小于真实值时，这个排名是 \(1/101\)。有任一号没有形成，该组的排名记为没有形成，不改分母。它不进入四项，也不是第五条门槛。

不设 0.97 或其他距离筛选。不按接触分数或 Pearson 丢弃重复。某一号没有形成该组 Precision@L，该组不成立。拟合失败会让该号的五个组都没有形成。

四项都成立时，结论句仍带上这一句：这是距离约束的列交换零模型；即使五个组都通过，也没有排除系统发育。估计器还会按该次自己的行重算序列权重，从而衰减一部分系统发育信号。

## 假设里的哪一句由哪一段落实

假设正文里按间隔组分开的合取，由第 2 节和第 4 节落实。对齐里的四项把「100 次都形成」和「严格大于每一次」写成两项；比较的仍是 Precision@L、MI 和 APC-MI。

「不重估真实比对的 \(J^\star\)，不改 Potts 公式和规范，也不改接触协议」，由第 1 节落实。

「零分布来自列多重集相同、生成目标是把汉明距离拉向原比对、没有位点间补偿机制的重复」，由算法 1 落实。预算 \(B=1677152\)、几何温度和「不把全矩阵放入内存」是方案写死的部分。\(B\) 次结束不是终态已经更近的判据。若以后要改拉近的程度，改的是这个 \(B\)，不是零模型的类别。

「相等不通过；少一项则该组归因不成立；其余指标不翻转；组与组可以分开成立；不写成已经排除系统发育」，由第 4 节落实。

「合取不进入 μFormer，也不替代适应度否决」，由第 1 节和第 3 节落实。

「编号 001 到 100 各生成、各拟合一次，缺一号不替换，不按距离相关剔除」，由算法 1、算法 3 和第 4 节落实。

含 gap、用正式 \(w_b\) 加权、无额外伪计数的 MI，由算法 2 落实。零频率项和自然对数是这一式里写明的部分。

「每个重复按自己的行重算序列权重，再用同一个估计重算接触分数」，由算法 3 落实。目标里的 \(W\) 用该次 \(M_{\mathrm{eff}}\)。
